EduFlow Workflow Guide

All 13 workflows imported into Pucho Studio: what each one does, what starts it, what to fill in before it runs, and how to spot extra copies.

Why there are so many

EduFlow has 13 workflows by design, one per job. A workflow that places AI calls, one that sends WhatsApps and one that runs on a timer each need their own trigger and steps, so they can't be merged without breaking the kit's limit of 14 steps and one AI judgement per path.

4 AI call agents 5 messages and saves 4 schedules

Every one is named Pucho EduFlow - <NAME>. More than 13 in Studio means copies: the folder was imported twice, an older file was imported, or Studio made a "Copy". Keep the newest of each name and delete the others. The checker below sorts your list for you.

How they connect

Who starts what

Buttons in the app start 8 workflows. The 4 schedules start on a timer and hand each student or fee to an action workflow. Saving attendance hands each absent student to ABSENCE.

Before the first real run

Setup, in this order

Each workflow's CHECKLIST.md in workflows/<NAME>/ lists every box. A workflow with an unfilled SET_IN_STUDIO_… value will not run.

  1. WhatsApp account and templates

    Get the six templates approved on whatsapp.pucho.ai: absence_alert, staff_alert, fee_payment_link, weekly_report, welcome, general_update. Paste the account id into SET_IN_STUDIO_WHATSAPP_ACCOUNT_ID and each template id into its SET_IN_STUDIO_TEMPLATE_ID_… box. eduflow_staff_alert takes 1 = staff name, 2 = alert text.

  2. Voice agents

    Pick the ai-voice-call agent for each caller: SET_IN_STUDIO_VOICE_AGENT_ADMISSION, _ACADEMIC, _FEE and _PARENT.

  3. Publish every workflow and copy its webhook URL

    Studio edits do nothing until you press Publish. Note each workflow's webhook URL. The same URL with /sync on the end waits for the answer.

  4. Hand-off URLs

    Paste the plain webhook URL of the receiving workflow, so the sender never waits on a call:

    • ATTENDANCE: SET_IN_STUDIO_WEBHOOK_ABSENCE
    • FEE_RUN: SET_IN_STUDIO_WEBHOOK_FEE_REMINDER
    • ACADEMIC_RUN: SET_IN_STUDIO_WEBHOOK_ACADEMIC_CALL
    • PARENT_RUN: SET_IN_STUDIO_WEBHOOK_PARENT_UPDATE

  5. The four schedules

    Fill SET_IN_STUDIO_APP_URL once the app has its domain, and SET_IN_STUDIO_INBOUND_TOKEN with the app's inbound token from Settings. The token never goes into git: build_deploy.py --inbound-token fills it into the deploy copies only.

  6. Connect the app

    In EduFlow, open Settings → Flow webhook URLs and set 8 workflows:

    • /sync URL for STUDENT_MANAGE, ATTENDANCE, FEE_REMINDER, PARENT_UPDATE and SEND_WHATSAPP. They have a quick action whose result the page shows.
    • Plain URL for ADMISSION_CALL, ABSENCE and ACADEMIC_CALL. They only take calls that run for minutes.
    • Leave SCORES empty: the app saves scores itself, in one transaction. The schedules are not called by the app.

    The header's "Workflows simulated" chip disappears once every workflow is wired.

  7. Test each one

    Paste the test payload from the workflow's CHECKLIST into Studio's test panel, then run one real record end to end from the app.

Not yet confirmed

These replies were read defensively, so an unexpected shape should not stop a workflow. One real run settles each.

  • Voice call settings and its reply (gap G1): the fields the call step sends (phone, name, language, context) and the shape of the call record. The AI reads the whole record, so a differently named transcript field still reaches it.
  • WhatsApp reply: an error or a refusal is recorded as Failed on the message and on the attendance WhatsApp Notice.
  • "Delivered" on the WhatsApp Notice needs WhatsApp's delivery callback (gap G5). Until then the workflows set Sent or Failed only.
  • The loop step used for hand-offs and per-row updates (14 places): the kit still lists its node type as to be confirmed against a real export.
  • Not built: ADMISSION_CALL's automatic retry 2 hours after an unanswered call. The Leads page's "Call again with AI" covers it.
